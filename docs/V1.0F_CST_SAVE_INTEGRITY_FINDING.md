# V1.0F CST save-integrity finding — ports/lumped elements lost when a saved gate project is reopened

- **Date:** 2026-09-13
- **Status:** OPEN — root cause identified, fix designed, not yet validated
- **Affects:** every gate project saved in the first build-only pass (G0–G4); all were built
  with macros executed from the VBA Macro Editor
- **Related runs:** `reports/cst_build_only/G0/20260913_105328/` (first pass),
  `reports/cst_build_only/G0/20260913_115800/` (fix attempt 1)

## Symptom

After saving a gate model and reopening the `.cst`, all ports (G0–G3: 2 ports; G4: 4 ports)
and all lumped elements are gone. The PCB/stack-up geometry is still there, so the loss is not
obvious in the 3D view.

## Root cause

- In CST, ports and lumped elements are **modeling-history objects**, not baked geometry.
  When a project is opened, they are recreated by replaying the project history.
- Macros executed from the **VBA Macro Editor** (`Macros → Open VBA Macro Editor → Open… → Run`)
  do **not** write a modeling history.
- Evidence: in the first-pass saves, `Model\3D\Model.mod` contains only the empty 209-byte
  history header, while `Model.dib` holds the full geometry. Geometry survives; history-based
  objects (ports, lumped elements) do not.

## Fix attempt 1 — structure macro (run 20260913_115800)

- A macro created with `Macros → Make VBA Macro` and marked **Structure Macro**, then executed
  via `Macros → Run Macro`, **is** recorded into the history:
  - History List shows one block `execute macro: RA_LNA_G0_ENV_PREFLIGHT_BUILD`;
  - `Model.mod` grew from 209 B to 1,432 B;
  - the project also stores the macro source (`RA_LNA_G0_ENV_PREFLIGHT_BUILD.mcs`, 7,620 B);
  - ports were present in-session at save time (`Model.dsn`: 2 ports).
- **Reopening still fails.** During "Processing history information":
  ```
  CST MICROWAVE STUDIO - History Error: Expecting an existing scalar var. (SetCommonUnitsAndMaterials)
  ```
- Cause: the recorder stores the top-level `Sub Main` statements **verbatim**, including calls
  to the macro's private helper subs (`SetCommonUnitsAndMaterials`, `BuildStack`, `AddBrickPEC`,
  `AddDiscretePortToL2`, `SetOpenBoundaries`) and the final `MsgBox`. History replay cannot
  resolve those private names, and the native commands inside the helper subs are not expanded.

## Fix direction (next)

Flatten each gate macro so that `Sub Main` contains **only native CST commands**:

- inline every helper sub (substitute the argument values used by `Sub Main`);
- unroll loops/expressions if the recorder stores them verbatim (confirm with a small
  structure-macro experiment before doing all gates);
- drop the trailing `MsgBox` (otherwise it pops up on every history replay at open);

then, per gate:

1. run the flattened macro as a structure macro in a fresh project;
2. save;
3. close and reopen the project;
4. verify ports/lumped elements are restored and no history error appears;
5. package and upload the run under `reports/cst_build_only/<gate>/<run_id>/`.

## Gate status impact

- **G0:** build-only execution was clean; `FINAL_STATUS=FAIL` for the first pass because of this
  persistence defect. Not approvable until the flattened re-run passes reopen verification.
- **G1–G4:** built locally in the first pass with the same defect (ports/lumped elements not
  retained on reopen). Their report packages will be produced after the fix is validated.
  The geometry builds themselves are preserved on the local CST workstation.
